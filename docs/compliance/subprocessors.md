# Operious AI — Subprocessor List

**Last updated:** 2026-07-05  
**Applies to:** Operious AI production environment (`operious-ai-imad.fly.dev`)

This list identifies every third party that processes customer data on behalf of Operious AI. "Customer data" means any data submitted through or generated by the Operious platform on behalf of a tenant, including ticket content, LLM prompts and completions, attachments, and identity information.

---

## Subprocessors

### 1. AWS Bedrock

| Field | Value |
|---|---|
| **Purpose** | LLM inference (Claude Haiku and Sonnet via Anthropic inference profiles) |
| **Data processed** | LLM prompts derived from customer ticket content; LLM completions; token usage metadata |
| **Region** | `us-east-1` (default; `LLM_AWS_REGION=us-east-1` in `config.py`) |
| **Grounding** | `LLM_PROVIDER=bedrock` in production config; `BEDROCK_DEFAULT_MODEL` and `BEDROCK_REASONING_MODEL` set to Anthropic inference-profile IDs |
| **AWS privacy / DPA** | https://aws.amazon.com/compliance/gdpr-center/ |

### 2. AWS SES (Simple Email Service)

| Field | Value |
|---|---|
| **Purpose** | Inbound email delivery to the platform; S3 raw-email fetch for large MIME bodies |
| **Data processed** | Inbound email content (subject, body, attachments) from customer email channels |
| **Region** | Configured via `LIVE_SES_REGION` (set via `fly secrets set`) |
| **Grounding** | `LIVE_SES_REGION`, `LIVE_SES_ACCESS_KEY_ID`, `LIVE_SES_SECRET_ACCESS_KEY` referenced in `config.py` |
| **AWS privacy / DPA** | https://aws.amazon.com/compliance/gdpr-center/ |

### 3. AWS S3

| Field | Value |
|---|---|
| **Purpose** | Storage of customer-submitted attachments (invoice photos, receipts, PDFs) |
| **Data processed** | Customer-submitted attachment bytes; encrypted at the application layer with AES-256-GCM before upload (S3 SSE is defense-in-depth only) |
| **Region** | Configured via `ATTACHMENTS_S3_REGION` (set via `fly secrets set`) |
| **Grounding** | `ATTACHMENTS_S3_BUCKET`, `ATTACHMENTS_S3_REGION`, `ATTACHMENTS_S3_ACCESS_KEY_ID`, `ATTACHMENTS_S3_SECRET_ACCESS_KEY` in `config.py` |
| **AWS privacy / DPA** | https://aws.amazon.com/compliance/gdpr-center/ |

### 4. Auth0

| Field | Value |
|---|---|
| **Purpose** | Authentication; JWT issuance and JWKS endpoint for bearer verification |
| **Data processed** | Principal identities (Auth0 user IDs, tenant assignments, role assignments); no ticket content |
| **Tenant / domain** | `operious-dev.uk.auth0.com` |
| **Grounding** | `AUTH0_DOMAIN`, `AUTH0_ISSUER`, `AUTH0_AUDIENCE`, `AUTH0_JWKS_URL` in `fly.toml` |
| **Auth0 DPA** | https://auth0.com/legal/dpa |

### 5. Fly.io

| Field | Value |
|---|---|
| **Purpose** | Infrastructure and compute; hosts all Operious backend processes |
| **Data processed** | All customer data in transit and at rest on process memory/disk during execution; Fly secrets store encrypted credentials |
| **Region** | `iad` (IAD, Northern Virginia) per `fly.toml` `primary_region` |
| **Grounding** | `app = "operious-ai-imad"` in `fly.toml`; 11 VM process groups defined |
| **Fly.io DPA** | https://fly.io/legal/privacy-policy |

### 6. Neon (PostgreSQL)

| Field | Value |
|---|---|
| **Purpose** | Primary relational database; stores all tenant-scoped records |
| **Data processed** | Session data, execution records, governance decisions, LLM audit records, data-protection keys, erasure requests, legal holds, all tenant configuration |
| **Isolation mechanism** | Row-Level Security enforced by Postgres role `operious_app` (`BYPASSRLS=False`) |
| **Grounding** | `DATABASE_URL` / `POSTGRES_*` settings in `config.py`; migrations in `apps/backend/migrations/versions/` |
| **Neon privacy** | https://neon.tech/privacy-policy |

### 7. Upstash / Redis

| Field | Value |
|---|---|
| **Purpose** | Rate-limit counters, idempotency keys, Celery result backend, governance policy pub/sub, quota tracking, semantic circuit-breaker state |
| **Data processed** | Request metadata (IP, tenant ID, principal ID) for rate-limit keys; idempotency key hashes; task result payloads; no raw ticket content |
| **Grounding** | `REDIS_URL` / `QUOTA_REDIS_URL` in `config.py`; `REDIS_REQUIRED_MAXMEMORY_POLICY=allkeys-lru` enforced at boot |
| **Upstash privacy** | https://upstash.com/static/trust/privacypolicy.pdf |

### 8. Sentry

| Field | Value |
|---|---|
| **Purpose** | Error tracking and exception monitoring |
| **Data processed** | Exception stack traces, request metadata, environment labels; `SENTRY_SEND_DEFAULT_PII=false` configured — PII scrubbing enabled |
| **Grounding** | `SENTRY_DSN` set via `fly secrets set`; `SENTRY_SEND_DEFAULT_PII = "false"` in `fly.toml` |
| **Sentry DPA** | https://sentry.io/legal/dpa/ |

### 9. CloudAMQP / RabbitMQ

| Field | Value |
|---|---|
| **Purpose** | Message broker for Celery task queues (alternative to Redis broker) |
| **Data processed** | Celery task payloads including execution IDs, tenant IDs, and task arguments; no raw ticket content in queue payloads |
| **Grounding** | `CELERY_BROKER_URL` and `RABBITMQ_*` settings in `config.py`; `QUEUE_DEPTH_BACKEND` can be `"rabbitmq"` |
| **CloudAMQP privacy** | https://www.cloudamqp.com/privacy_policy.html |

### 10. OpenAI

| Field | Value |
|---|---|
| **Purpose** | Text embeddings for knowledge base and semantic search |
| **Data processed** | Tenant knowledge document text; customer ticket text used for semantic matching; no raw PII fields are sent to the embedding endpoint without application-layer controls |
| **Grounding** | `OPENAI_API_KEY` configured; `OPENAI_EMBEDDING_MODEL=text-embedding-3-small`; `EMBEDDING_DEFAULT_PROVIDER=openai` in `config.py` |
| **OpenAI DPA** | https://openai.com/policies/data-processing-addendum |

### 11. GCP Cloud KMS

| Field | Value |
|---|---|
| **Purpose** | Key custody for data-protection master key ring and tenant credential DEKs |
| **Data processed** | KMS-wrapped ciphertext of master key material; no customer content |
| **Grounding** | `CREDENTIAL_KMS_BACKEND=gcp`, `DATA_PROTECTION_KMS_BACKEND=gcp`, `OPERIOUS_KMS_KEY_RESOURCE` in `config.py`; `GOOGLE_APPLICATION_CREDENTIALS` set via `fly secrets set` |
| **GCP DPA** | https://cloud.google.com/terms/data-processing-addendum |
